# 복원 기록

2026년 10월 24일에 `FileSearch.exe` 배포본에서 복원했어요.

원본 실행 파일 SHA-256은 다음과 같아요.

```text
11f110d4da99fd4db4c3b53c788bcb2fb3dddcc8bc1956799f10eaffd992c5a6
```

원본 폴더와 기존 분석 결과는 보존했어요. 실제 개인 파일을 탐색·이동하거나 실제 사용자 설정 파일을 변경하지 않았어요.

## 복원 방식과 비교 범위

PyInstaller의 CArchive와 PYZ에서 프로젝트 고유 모듈 18개를 추출했어요. 원본 Python 3.13.0 코드 객체를 역어셈블하고, 일반 Python 구문으로 소스를 재구성했어요. 앱 실행에 `marshal`, `exec` 또는 원본 바이트코드를 사용하는 우회 로더는 넣지 않았어요.

CPython 3.13.0으로 다시 컴파일한 결과, 166개 코드 객체의 `co_code`와 `co_exceptiontable`이 모두 원본과 바이트 단위로 같았어요. 인자 수, 플래그, 스택 크기, 지역·전역·클로저 변수 이름 및 상수도 비교했어요.

원래 파일의 공백·주석·줄 배치는 복원할 수 없으므로 `co_filename`, `co_firstlineno`, `co_linetable`, 클래스의 `__firstlineno__` 소스 위치 값은 비교에서 제외했어요. 이는 소스 파일 전체가 글자 단위로 같다는 주장이 아니에요.

`reference_bytecode.zip`은 비교용 원본 코드 객체를 보존한 자료예요. `.pyc` 헤더는 추출 과정에서 새로 붙였고, 그 뒤의 marshal 데이터는 원본에서 추출한 내용이에요. 앱은 이 ZIP을 읽지 않아요. `tools/verify_recovery.py`만 검증할 때 읽고, 코드 객체를 실행하지 않아요.

## 실제 실행 검사

Windows에서 Python 3.13.0, PySide6 6.12.0으로 검사했어요.

- 코어 회귀 테스트 17개: 한글 정규화, 검색 조건·정렬, 하위 폴더·제외 경로, 중복 파일명, 실제 복사·이동, 복사 실패 정리, 공간 계산, 취소, 작업 기록·중단 복구, 설정 저장을 확인했어요.
- 다른 드라이브 이동 분기는 드라이브 판정만 모의 처리하고 실제 임시 파일 복사·삭제를 실행했어요. 실제 외장 드라이브나 네트워크 공유에서의 검증은 아니에요.
- GUI 23개 검사 항목: 메인 창과 대화상자 생성, 검색 결과, 미리보기 선택, 체크 개수, 정렬, 설정 저장, 파일 형식 선택, 실제 QThread 탐색·복사, 진행 창 취소 신호를 확인했어요.
- 화면 캡처는 Qt의 offscreen 모드에서 생성했어요. 검사 환경의 offscreen 글꼴 로딩을 위해 테스트 코드에서 Windows 글꼴을 명시적으로 불러왔고, 앱 소스의 글꼴 처리는 변경하지 않았어요.
- PyInstaller 6.22.3으로 onedir/windowed 빌드를 완료했어요. 재빌드 EXE의 별도 화면 실행 검증은 포함하지 않았어요.

파일 연결 프로그램 열기와 탐색기 열기는 실제 사용자 앱을 실행하는 대신 원본 바이트코드 일치로 검증했어요. 실제 자료의 이동이나 운영 환경에서의 중단·정전 시험은 하지 않았어요.

검증 자료는 `verification.json`, `core_tests.txt`, `gui_results.json`, `build_log.txt`, `environment.txt`, `screenshots/`에 있어요.

## 새로 작성한 파일

`README.md`, `pyproject.toml`, `requirements*.txt`, `FileSearch.spec`, `run.cmd`, `.gitignore`, `tests/`, `tools/`, `recovery/`는 복원 후 새로 작성한 작업 지원 파일이에요. `pyproject.toml`의 `0.1.0`은 복원 프로젝트 식별용 버전이며 원래 앱의 버전을 알아낸 것이 아니에요. 원래 PyInstaller 버전은 확정하지 않았고 재빌드 검증에는 6.22.3을 사용했어요.

Git 이력, 원래 주석, 배포에 포함되지 않은 파일은 복구하지 못해요. 원래 패키지 잠금 파일도 없으므로 원본에서 확인한 PySide6 버전을 고정하고, 재빌드에 사용한 환경을 별도로 기록했어요.

## 원본 로직의 기존 제약

동작을 바꾸는 수정은 하지 않았어요. 이어서 개발할 때 아래 부분을 검토할 수 있어요.

- 중단된 이동을 마무리할 때 원본과 사본의 **파일 크기**를 비교해요. 내용 해시 비교는 하지 않아요.
- 기록 파일의 마지막 줄이 쓰다 끊긴 경우, 파싱 실패한 줄은 건너뛰지만 다음 기록이 그 깨진 줄 뒤에 바로 붙을 수 있어요. 복구 기록을 다시 읽는 과정에 영향을 줄 수 있어요.
- 본문·태그 검색, 태그 관리와 일부 사이드바 메뉴는 원래 미완성 상태예요.
